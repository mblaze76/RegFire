Wallet passes

Private provider setup. Organizers customize confirmation content in their flow; they never see these credentials.

Before enabling

Apple requires an active Developer membership, Pass Type ID certificate and matching private key, and its WWDR intermediate certificate. Google requires an approved Wallet issuer, existing generic class and a service account authorized for that issuer. Supply existing provider-issued files privately; RegFire does not create accounts, certificates or keys.

Local checks verify structure and signing material. A real-device test is still required before claiming production readiness. Sample and sandbox registrations do not issue usable passes. Downloading a pass does not send an email.
