# Separate live attendee preview

Open an event's **Registration page**, then click the prominent **Open live preview ↗** button. It requests a separate window containing the attendee-style registration form and demographics, without the organizer shell. If the browser opens a tab instead, drag that tab into a separate window and move it to the second monitor. The preview toolbar contains **Full screen**. Browser support and user gestures govern fullscreen; a fallback message instructs maximizing a separate window if fullscreen is unavailable. Fullscreen cannot automatically move a window to another monitor.

An **Open preview in a new tab** link remains available next to the organizer's launch message, including when popups are blocked. Do not bookmark a session-specific preview as a permanent event URL; launch it from the event's organizer page.

Unsaved title/introduction, RegTypes/prices, preview time, fields/order/visibility and selected logo/background/fade are sent from the editor. Demographic definition edits also stream while their organizer page is open. Validations and branch evaluation run through the local server. Invalid draft prices show an explicit error rather than a stale valid price. Select a RegType independently in the preview. Changing the organizer's selected type also updates it.

Demographics also embeds this renderer beside its editor, labeled as a non-collecting preview. Launching from Demographics adds `view=demographics` and opens a demographics-only window; launching from Registration retains the existing registration preview. Window names include the view to prevent reusing the wrong preview destination.

The separate window explicitly names the current website preview and provides a **Preview page** selector for Registration or Demographics. The embedded demographics preview stays fixed to Demographics. Chrome verification confirmed that an unsaved question-label edit appeared in both demographics previews, native full screen worked, and selecting Workshops then Event technology revealed the nested follow-up. The temporary label edit was discarded after verification, preserving the saved event.

The preview uses the active editor's in-memory definition and the other page's saved definition. Switching organizer sections retains the existing save/discard prompt; discarding intentionally removes those unsaved edits. The preview is not a second editor and cannot save definitions. Contact/demographic answers remain temporary and are not stored as attendees. Hidden questions are pruned from branch evaluation. Reloading clears answers.

A same-origin BroadcastChannel is scoped by event UUID and editor-session UUID. Every message checks both IDs, protocol, epoch and sequence. Switching to another event pauses the old preview and never supplies the new event's data. Closing/disconnecting the editor shows the last received draft with a disconnected notice. Reopening/restoring the same editor tab can reconnect; otherwise use Open live preview again from the desired editor. Tabs without active preview subscribers do not continuously fetch page definitions. No credentials, membership configuration or member roster are sent over this channel.

Registration prices here are configuration previews, not evidence of membership eligibility. Use Membership's dedicated check preview to test its policies. No public attendee registration, payment, review submission or publishing exists.

For artwork with background fade below 50%, both the embedded Registration renderer and shared live renderer use solid white supporting text and a pale-gold heading with stronger weights. The pane remains transparent and text shadows remain disabled. This display-only contrast treatment overrides title/intro colors in those previews without changing saved appearance values; at higher fade or without artwork, configured colors apply normally. Verified in Chrome on the user's Registration editor, separate Registration, and Demographics views on October 1.
